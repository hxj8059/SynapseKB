# 已知限制与路线图

## 当前限制

- V1 统一向量维度默认 1536；更换维度需要重建 Chunk 向量和 HNSW 索引。
- 中文关键词召回使用 Jieba，不包含行业定制词典管理界面。
- URL 导入不执行 JavaScript，仅抓取服务端可见 HTML。
- Wiki V1 已支持知识库自定义节点类型、节点 Markdown、页面双链、来源溯源、
  有界历史节点召回、持久别名与消歧结论、孤立节点检查和可撤销的高置信模型合并；尚未实现
  面向大语料的全局聚类目录重排、合并后的 LLM 语义压缩或人物/组织/事件级本体。
- 保护区块以显式 Markdown 片段保存和合并，尚无可视化冲突解决器。
- 对象存储直传 API 已实现；Web 首版仍使用受限中转上传，超大文件上传进度与分片
  前端是下一步产品化工作。
- Agent SSE、步骤与引用事件已提供，Web 首版以状态轮询显示最终结果，尚未呈现完整
  的实时工具时间线；Web 当前提供 Agent 创建配置，存量 Agent 的可视化编辑仍待完善。
- 通用部署参数仍通过 `.env` 管理；模型、OCR 和对象存储支持管理员运行时配置，
  其他基础设施参数不进入动态配置中心。
- 模型费用只记录可计算的 Token/耗时指标，不内置会快速过期的供应商价格表。
- 当前自动浏览器用例覆盖登录壳层；带 PostgreSQL、Redis 与真实 OCR 的完整
  端到端验收需要在隔离部署环境执行。
- 不提供多租户、企业 SSO、第三方数据源同步、外部工具执行或多 Agent 协作。

## 后续路线

1. 以 10,000 文档/300 万 Chunk 数据集执行检索、任务恢复与 30 并发聊天压测。
2. Web 对象存储直传、分片/断点续传和逐文件上传进度。
3. 检索基准集、离线评估与面向具体业务的词典/切块调优。
4. Embedding 维度在线迁移和双索引无停机切换。
5. Wiki 大规模分层聚类目录、保护区块可视化冲突解决和实时 Agent 工具时间线。
6. 完整费用预算、告警、模型降级和云厂商实网兼容认证。
