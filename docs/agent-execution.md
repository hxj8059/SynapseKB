# Agent 执行诊断与作答优化

更新日期：2026-10-16。本次更新不新增数据库迁移或 API 路径。

## 已定位的问题

一次“最近一个月的投资机会”任务完成了 16 个工具步骤、保存了 33 条引用，却在最终答案
生成阶段连续三轮耗尽每轮 300 秒预算。时间筛选正常，最终请求约 48,697 字符；模型调用
采用非流式输出，SDK 的 180 秒请求超时与自动重试叠加，使外层超时只剩下空的 `TimeoutError`。
两次读取使用了检索结果中不存在的文档 ID，造成了额外无效步骤。

使用同一份已保存证据，关闭最终作答推理并启用流式输出后，回放约 1.9 秒收到正文、32 秒
完成。该结果表明作答链路可以改善，但不能据此排除原失败时段的上游或网络波动。

## 新的执行策略

- 时间解析、工具选择、工具执行、最终作答分别标识阶段。时间解析最多使用总预算的 20%，
  且不超过 45 秒；工具阶段为最终答案预留总预算的 40%，最多 120 秒。
- 工具决策请求不叠加 SDK 自动重试，单次等待最多 45 秒；时间预算耗尽时，转为基于已有
  证据作答。配置的工具步数仍是上限，不要求必须用满。
- 最终答案逐段流式生成，仅在这个阶段请求关闭推理；不修改管理员保存的模型设置。
  单次流读取等待不超过 30 秒。首次生成与一次恢复共享最终作答时间预算。
- 首次整理使用至多 24,000 字符的证据，按文档轮流选取片段，合并重复来源文本，保留原始
  引用编号、文档标识、标题和来源时间。失败时缩减到 12,000 字符，并将该次恢复的输出上限
  限制为配置上限与 4,000 tokens 的较小值。
- 普通工具决策历史不再回传隐藏推理内容，并始终保留原始问题。读取正文必须使用用户提供
  或检索结果实际返回的完整 ID；已有的知识库权限和时间检查仍然执行。
- 最终恢复耗尽后直接报告失败，不再让队列重复执行三轮同样的最终请求。其他可恢复任务
  错误仍沿用已有投递恢复机制。Worker 的硬限制覆盖 API 允许的最长 900 秒配置及清理时间。

## 完整性与界面

正文生成时定期保存到 `AgentRun.result`，页面通过原有轮询逐步展示。只有收到完整结束标记、
正文有效且引用编号来自已取得证据时，才允许标记完成。截断、断流、空正文、工具协议文本和
不存在的引用编号均不能当作完整答案；取消操作不会触发恢复重试。

生成失败时保留有效的部分内容和检索记录，页面同时展示“未完成”提示与错误原因。
客户端不能仅凭 `result` 非空判断成功，必须检查 `status == "completed"`。

SSE 新增 `assistant.reset` 事件，在每次最终生成尝试开始时发送；消费方应先清空上一轮
部分正文，再累积新的 `assistant.delta`。`run.error` 仍表示终止失败，`run.completed`
仍表示完整成功。

## 日志排查顺序

1. 根据任务 ID 查看 `agent_runs` 状态、`error_summary` 和 `state_json.phase`，以及
   `task_dispatches.attempts`，区分时间解析、检索和最终作答阶段。
2. 核对 `agent_steps` 的实际时间条件、无效 ID 和重复读取；不要把单个工具失败直接等同于
   整个任务失败。
3. 通过日志中的 `run_id`、`phase` 关联模型调用。流式调用记录 `quota_wait_ms`（并发等待）、
   `response_ms`（响应建立）、`first_token_ms`（首次正文）、总耗时、输入/输出字符数、
   推理字符数、结束标记和错误类型。这些指标不包含正文或 API Key。
4. 用短问题探测连接，再回放已保存证据，最后重跑完整任务。分别比较首字延迟、总耗时、
   实际 token 用量和引用完整性；避免只通过增大总超时掩盖问题。

升级时重建后端和 Web 镜像，并更新 API、Agent Worker、相关后端服务与 Web；重新加载
Nginx 以解析更新后的容器地址。已失败的历史记录不会被自动改写，应重新发起任务验证。

## 验证记录

- 245 项后端单元测试、28 项前端测试通过；相关 Python 模块通过 Ruff、mypy，前端通过
  TypeScript 检查和生产构建。
- 故障注入覆盖断流、截断、空正文、错误引用、用户取消、存储故障、部分答案保留，以及
  队列不再重复执行已耗尽恢复的最终请求。
- 候选镜像回放原任务保存的证据，首次正文约 1.9 秒、总耗时约 34 秒，一次完成。
  输入从约 48,697 字符降到 24,538 字符，实测输入 token 从 30,075 降到 14,631；
  返回引用编号全部来自已取得证据。耗时和 token 为该次实测，不代表性能保证。
